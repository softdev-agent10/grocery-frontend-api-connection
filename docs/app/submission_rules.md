# Task Submission Rules

1. **Branch Naming**  
   - Create a new branch from the main branch.  
   - Name the branch following this pattern:  
     `feature/<your-branch-name>`  
   - Example: `feature/user-profile-page`

2. **Code Implementation**  
   - Implement all task requirements in your branch.  
   - Follow the team's coding standards and best practices.  
   - Ensure your code is clean, modular, and properly documented.

3. **Commits**  
   - Make frequent commits during your work.  
   - Use clear and descriptive commit messages.  
   - Example: "Add user profile layout" or "Fetch user data from API"

4. **Solution File**  
   - Create a file named `solution.md` in the root of your branch.  
   - Follow this structure:  
     - Branch Name  
     - Description  
     - Approach  
     - Challenges  
     - Next Steps  
   - Be detailed so reviewers understand your process.

5. **Pull Request**  
   - Once you have implemented the task and added the solution file, create a pull request (PR) from your branch into the main branch.  
   - In the PR description, link to your `solution.md` file so the reviewer can easily locate it.

6. **Review**  
   - After submission, a reviewer will check your code, provide feedback, and approve or request changes.

7. **Timeliness**  
   - Submit your task by the agreed-upon deadline.  
   - Communicate early if you face any blockers.
